# Power Apps Canvas Pack — two skills that make Canvas YAML compile on the first try

**EN** — A pair of complementary AI-agent skills for Power Apps **Canvas** authoring in YAML (`.pa.yaml`):
one generates screens from screenshots, mockups or text, the other is a **machine-verified reference layer**
(117 controls extracted live from the Microsoft Canvas Authoring MCP on 2026-11-13, 673 enum rows with literal
Power Fx identities, a compiled properties matrix, and 15 templates **all proven `compile_canvas` PASSED**).
Chain them and the pipeline is: image → design → machine truth → compiled app.

## Machine corrections you should know about

- `GroupContainer` + `Variant: GridLayout` **compiles** — the widely repeated "GridLayout unsupported" legend is false.
- A made-up **higher** version (`TextInput@99.99.99`) compiles too; the real PA2105 trigger is **mixing old versions**.
- `Control: Screen` does break, but the compiler says `YamlInvalidSyntax` / `Unknown control type 'Screen'` — PA21xx labels are Studio wordings, not compiler output.
- Real machine "do not use" guidance exists for exactly **three** controls: `Button`, `DataGrid`, `DataTable` (use the Modern equivalents).
- `ModernTextInput` exposes `Text`, **not** `Value`; `SizeRules` **does not exist** in the service (0 occurrences) — never emit it.

## Prerequisites

Canvas Authoring MCP server: `dnx Microsoft.PowerApps.CanvasAuthoring.McpServer --yes` (needs .NET 10 SDK).
A coauthoring browser session is required for `sync_canvas` / paste-code round-trips; **static validation works
without it** (`compile_canvas` answers with a coauthoring warning but full diagnostics).

## Install

- **OpenCode**: drop the two folders into your skills directory (the one your `opencode.json` `"skills"` key points at) and the skills load on next session.
- **Claude Code / skills.sh**: `npx skills add bastiencltd/powerapps-canvas-pack` then use `/canvas-apps-ui-gen`, or read `skills/powerapps-canvas-yaml/SKILL.md` as always-on context.

## Example prompt (full pipeline)

> Reproduce the UI of the attached screenshot in Power Apps Canvas YAML.
> Phase 1: generate with canvas-apps-ui-gen (replication mode). Its output is a CANDIDATE, never a delivery.
> Phase 2: apply powerapps-canvas-yaml — 4-step reread, machine rules win over any ui-gen output or legend.
> Phase 3: write the full app (App/Screen1/_EditorState), compile with compile_canvas until "Validation PASSED", iterate on every diagnostic without deleting unverified properties.
> Report: image element → controls used, unreproduced elements, last raw compile output.

## Limitations (stated honestly, dated)

Audit was run against a single app session: 0 data sources, 1 connected API. `required: null` in the references means
*the service does not report it*, not *optional*. 14 of the 21 documented traps were not reproducible by machine and
are flagged as such. Control versions drift — re-audit before trusting against a newer tenant.
